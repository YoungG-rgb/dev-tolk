# Технические решения — dev-tolk (локальный транскрибатор)

Состояние на 2026-10-18 (обновлено после ответов на Q-01 … Q-16). Документ фиксирует результаты технической разведки, принятые и предлагаемые решения, альтернативы и открытые вопросы.

Метки достоверности:

- **[Факт]** — подтверждено первоисточником (ссылка рядом или в разделе «Источники»).
- **[Оценка]** — вывод или расчёт на основе фактов; требует проверки измерением.
- **[Неизвестно]** — данных нет; закрывается задачей из `TASKS.md`.

Статусы решений:

- **Предложено** — рекомендация, ждёт подтверждения владельца продукта.
- **Принято** — решение не требует отдельного подтверждения: оно следует из требований или не имеет реальных альтернатив.
- **После бенчмарка** — окончательный выбор зависит от измерений (`BENCHMARK_PLAN.md`).

> Ни одно утверждение о скорости и качестве распознавания в этом документе не является результатом наших измерений. Измерения ещё не выполнены.

```
┌──────────────────────── Tauri 2 приложение (процесс UI) ────────────────────────┐
│  WebView: Svelte + TypeScript UI (только отображение и ввод, без бизнес-логики) │
│        │ invoke() / Channel (прогресс)                                          │
│  Rust core:                                                                     │
│   • commands — тонкий слой команд для UI                                        │
│   • queue    — очередь заданий, один исполнитель, машина состояний              │
│   • store    — SQLite (rusqlite, WAL) + файлы заданий на диске                  │
│   • models   — каталог моделей, загрузка, SHA-256, рекомендация по RAM          │
│   • export   — DOCX (docx-rs)                                                   │
│   • glossary — словарь терминов: хранение, импорт/экспорт, подсказка движку     │
└───────────────┬─────────────────────────────────────────────────────────────────┘
                │ запуск дочернего процесса на каждое задание:
                │ аргументы CLI → stdout JSON Lines (прогресс/сегменты) → файл результата
┌───────────────▼─────────────────────────────────────────────────────────────────┐
│ tolk-engine (sidecar, отдельный Rust-бинарник)                                  │
│   probe:      проверка файла (контейнер, кодек, длительность)                   │
│   extract:    аудиодорожка из видео MP4/MOV → WAV 16 кГц моно                   │
│   transcribe: symphonia → моно 16 кГц (rubato) → whisper.cpp + Silero VAD        │
│               (Metal на Apple Silicon, CPU/Vulkan на Windows)                   │
└─────────────────────────────────────────────────────────────────────────────────┘
```

Хранение (каталог `app_local_data_dir`: `%LOCALAPPDATA%\<id>` на Windows, `~/Library/Application Support/<id>` на macOS):

```

  models/                     установленные модели (*.bin), *.part — незавершённые загрузки

    source.<ext>              копия импортированного аудио
    original.json             неизменяемый результат движка (сегменты с таймкодами)

  tmp/                        временные файлы; очищается при старте
  logs/                       журналы приложения и движка
```

## 4. Решения

### TD-01. Оболочка: Tauri 2 (ветка 2.x) + TypeScript — **Принято**
- **Почему:** нативный WebView вместо встроенного Chromium, Rust-ядро, сайдкары и подпись поддерживаются бандлером, на этом стеке работают зрелые приложения (Handy, Vibe, Meetily).
- **Альтернативы:**
  - Electron — +100 МБ и Node-процесс.
  - Чистый нативный UI на двух ОС — двойная работа.
- **Ограничение:** Tauri 3 (alpha) не использовать.

### TD-02. Основной движок: whisper.cpp, модель по умолчанию large-v3-turbo q5_0 — **После бенчмарка**
- **Почему:**
  - MIT-лицензия для движка и весов.
  - Один движок с аппаратным ускорением на обеих ОС: Metal, Vulkan, CPU.
  - Встроенный VAD.
  - Есть таймкоды сегментов, пунктуация и регистр.
  - Модель весит 574 МБ.
- **Кандидаты на замену:**
  - GigaAM v3 e2e — через sherpa-onnx (TD-03).
  - turbo q8_0 — если q5_0 заметно хуже по качеству.
  - medium q5_0 или small q5_1 — для слабых машин.
- **Условие окончательного выбора:** измерения WER/CER, времени и пиковой памяти на наших записях (BENCHMARK_PLAN, этап 1).

### TD-03. Альтернативный движок: оценивать GigaAM v3 наравне с Parakeet; в MVP — один движок — **После бенчмарка**
- **Parakeet TDT v3:**
  - Runtime есть: sherpa-onnx.
  - Лицензия CC-BY-4.0 допустима при атрибуции.
  - Поставить можно на обе ОС.
  - Но по опубликованным цифрам на русском он **не лучше** Whisper turbo, а длинное аудио требует нарезки через VAD.
  - Только качество не оправдывает второй runtime (ONNX Runtime, около 15–35 МБ) и второй конвейер [Оценка].
- **GigaAM v3** (MIT, модель для русского, ~165 МБ, быстро работает на CPU [Факт по оценке вендора]) — кандидат, который **может заменить** Whisper. Особенно на машинах с 8 ГБ.
- **Решение:**
  - Бенчмарк сравнивает Whisper, Parakeet и GigaAM одним протоколом.
  - В MVP идёт **один** движок — победитель.
  - Второй движок добавляется только при доказанной пользе. Например: Whisper по умолчанию и GigaAM для 8 ГБ.
- **Если побеждает GigaAM:** движок внутри `tolk-engine` меняется на sherpa-onnx, остальная архитектура не меняется (см. TD-04).

### TD-04. Интеграция движка: отдельный процесс `tolk-engine` (сайдкар) — **Принято** (Q-01, 2026-10-18)
- **Суть:** Rust CLI в том же workspace. Принимает аргументы, пишет прогресс в stdout в формате JSON Lines, результат пишет в файл через временный файл и `rename`.
- **Почему:**
  - **Прототип — это и есть движок.** CLI из этапа прототипирования без переделки становится компонентом приложения.
  - **Отмена гарантирована.** Процесс завершается принудительно, а не ждёт `abort_callback`. Память модели гарантированно освобождается ОС.
  - **Изоляция сбоев.** Падение GPU-драйвера (Vulkan, известны issues), OOM или panic в декодере не роняют UI, и задание корректно помечается FAILED.
  - **Пиковую память удобно измерять** отдельно от UI.
  - **Движок меняется в одном месте:** whisper.cpp ↔ sherpa-onnx.
  - Подписывать сайдкары Tauri умеет сам.
- **Цена:** второй бинарник и простой протокол stdout. Модель загружается на каждое задание, это секунды [Оценка]; при 5–6 заданиях в день это несущественно.
- **Отклонённая альтернатива:** whisper.cpp внутри процесса приложения (как в Handy). Меньше бинарников, но сбой движка роняет приложение, а отмена зависит от callback'ов.
- **Как избежать дублирования логики:** проверка файлов (`probe`) тоже выполняется движком. Приложение не линкует аудио-библиотеки.

### TD-05. Привязка Rust ↔ whisper.cpp — **После прототипа**
Варианты для `tolk-engine`, в порядке проверки:
1. `whisper-rs` 0.16 — зрелый API, но whisper.cpp 1.8.3 без исправления #3570 для VAD + Vulkan.
2. `transcribe-cpp` 0.4 — свежий whisper.cpp и dynamic-backends, но проект молодой.
3. Тонкий собственный FFI (bindgen) к whisper.cpp, закреплённому как git submodule на релизном теге.

Критерии выбора: актуальность whisper.cpp; работающие VAD, progress и abort; сборка на Windows с Vulkan и `GGML_NATIVE=OFF`; отсутствие падений на эталонных файлах.

Базовую линию качества сначала снимаем `whisper-cli` upstream v1.9.5, чтобы отделить качество модели от качества привязки.

### TD-06. Аппаратное ускорение — **Принято** для macOS; для Windows — **После бенчмарка**
- **macOS Apple Silicon:**
  - Metal (по умолчанию в whisper.cpp).
  - Core ML **не** использовать в MVP: +1,17 ГБ загрузки и долгая первая компиляция модели.
- **Windows x64:**
  - CPU-сборка (AVX2, `GGML_NATIVE=OFF`) — обязательная базовая.
  - Vulkan — опционально, по результатам бенчмарка, с автоматическим откатом на CPU и настройкой «Отключить GPU».
  - Нужно проверить запуск на машине без драйвера Vulkan (`vulkan-1.dll`). Решения: dynamic-backends или два варианта движка.
  - CUDA — не в MVP (сотни МБ).
- **Intel Mac:** специальной оптимизации и отдельной сборки в MVP нет (Q-02, Q-13). Если среди сотрудников найдутся Intel Mac — поддержка добавляется отдельным этапом после MVP: x64-сборка, только CPU.
- **Без привязки к Apple Silicon (Q-13).** Архитектура и выбор движка не должны зависеть от Apple Silicon:
  - движок — переносимый C/C++ (whisper.cpp или sherpa-onnx) с CPU-бэкендом на всех платформах; Metal — только ускорение, а не обязательное условие;
  - `tolk-engine` собирается под target triple, поэтому новая платформа — это новая сборка, а не переделка;
  - каталог моделей уже содержит облегчённые и квантованные варианты (TD-14);
  - параметры производительности (`--threads`, `--no-gpu`) есть в протоколе движка с MVP;
  - в UI в MVP не выносятся.
  
  Дальнейшее расширение (Intel Mac, слабые ПК, настройки производительности в UI) — отдельный этап после проверки спроса и замеров. MVP ради гипотетической совместимости не усложняется.
- **Windows ARM:** не в MVP.

### TD-07. Аудио: Symphonia 0.6 + libopus + rubato 5, без FFmpeg — **Принято** (Q-09), с проверкой матрицей форматов (MVP-035)
- **Форматы MVP:**
  - аудио: MP3, M4A (AAC-LC, ALAC), WAV, FLAC, OGG Vorbis;
  - **Opus** в OGG и WebM/MKV (голосовые из мессенджеров) — через `symphonia-adapter-libopus` (libopus собирается в составе, MIT/Apache + BSD-3-Clause у libopus [проверить в MVP-029]);
  - **аудиодорожка из видео MP4/MOV** — демультиплексор `isomp4` берёт первую аудиодорожку с поддерживаемым кодеком (обычно AAC-LC [Оценка]). Видеопоток не декодируется.
- **Не поддерживается** (понятная ошибка «кодек не поддерживается»):
  - HE-AAC (v1/v2);
  - AC-3/E-AC-3;
  - AMR;
  - WMA;
  - видео без аудиодорожки.
- **[Неизвестно] Совместимость с MOV (QuickTime).** Насколько `isomp4` в Symphonia корректно читает MOV-файлы с iPhone и камер, включая дорожки PCM (`lpcm`/`sowt`). Проверяется в MVP-035 на реальных образцах с Windows и macOS.
- **Почему не FFmpeg:**
  - чистый Rust (плюс маленький libopus);
  - нет отдельного бинарника, лишнего для поставки;
  - нет обязательств LGPL и собственных сборок FFmpeg на двух ОС;
  - размер прибавки — единицы МБ [Оценка], против 77–171 МБ у готовых LGPL-сборок FFmpeg для Windows [Факт].
- **Условие пересмотра:** если матрица MVP-035 покажет, что заметная доля реальных файлов пользователей не декодируется (HE-AAC, AC-3 в MOV и т.п.), рассмотреть один из вариантов:
  - (а) собственная audio-only LGPL-сборка FFmpeg, динамическая, с исходниками и уведомлениями (~3–8 МБ [Оценка]);
  - (б) системные декодеры ОС: AVFoundation и Media Foundation (~300–500 строк FFI на ОС [Оценка]).

  Решение фиксируется в TD-07 по результатам MVP-035.
- **Защита:** декодирование выполняется в процессе движка, поэтому panic на битом MP4 приводит к ошибке задания, а не к падению приложения.
- **Результаты проверки в MVP-008 (2026-10-18, macOS arm64, синтетические тон-файлы от ffmpeg и afconvert; реальных записей и Windows пока нет):**
  - **Работает:** MP3, AAC-LC в M4A и MP4/MOV (с видеопотоком и без), ALAC, WAV (8/16/44,1 кГц), PCM в MOV, FLAC, Vorbis, Opus в OGG и WebM. Для каждого проверены длительность (±0,1 с, у AAC +40 мс из-за задержки кодера, которую Symphonia не обрезает) и высота тона после ресемплинга.
  - **Opus:** libopus собирается крейтом `opusic-sys` через `cc` на macOS без дополнительных инструментов; для Windows (MSVC) сборка не проверена.
  - **Не поддерживается, но распознаётся с понятной ошибкой `UNSUPPORTED_CODEC`:** AC-3 (в M4A/MP4, в том числе рядом с видео). AMR и WMA не проверялись: нет образцов.
  - **HE-AAC:** файл с неявным сигналом SBR (`afconvert -d aach`) декодируется базовым слоем без SBR, длительность и тон верны, верхняя полоса (выше ~11 кГц) отсутствует. Для ASR на 16 кГц это не критично [Оценка, проверить на реальных файлах в MVP-035]. Если профиль HE указан явно, файл отклоняется как `UNSUPPORTED_CODEC` («HE-AAC»): поведение декодера на таких файлах не проверено.
  - **Оборванные файлы:** обрезанный MP3 даёт часть звука и флаг `incomplete`; MP4/M4A без индекса `moov` — `CORRUPT_FILE`. Пропуск мелкого повреждения в середине MP3 не флагуется, если потеряно меньше секунды и меньше 3%.
  - **Скорость и память (синтетические 60-минутные файлы, release):** `probe` — до 0,23 с (MP3), остальные — меньше 0,01 с; `extract` 60 минут — 1,5–3,7 с, пиковая память процесса 2,5–3,6 МБ (декодирование потоковое, весь звук в памяти не держится).
  - **Размер:** release-бинарник `tolk-engine` (arm64, fat LTO, strip) — 2,28 МБ; пустая программа на Rust — 0,34 МБ. Все декодеры, libopus, ресемплер и разбор JSON дают около +1,9 МБ. Динамических зависимостей кроме системных (`libSystem`, `libiconv`) нет. Размер на Windows не измерен.
  - **Лицензии:** symphonia — MPL-2.0 (файловое копилефт, исходники не изменяются), rubato — MIT/Apache; libopus — BSD-3-Clause; окончательная проверка — MVP-029.
  - **Остаётся:** реальные записи (iPhone MOV с HEVC и AAC, Telegram/WhatsApp, Zoom) и Windows — MVP-035.

### TD-08. Хранение: SQLite (rusqlite `bundled`) для метаданных, файлы на диске для аудио и транскриптов — **Принято**
- Режим WAL, `synchronous=NORMAL`, `foreign_keys=ON`. Миграции через `PRAGMA user_version` (или `rusqlite_migration`).
- Сущности: `jobs`, `settings`. Установленные модели определяются по файлам в `models/` и встроенному каталогу, отдельная таблица не нужна.
- Транскрипт хранится JSON-файлом (сегменты `start_ms/end_ms/text`), а не в БД:
  - `original.json` не меняется;
  - `transcript.json` — рабочая версия.
- Запись файлов атомарная: временный файл в том же каталоге → `sync_all` → `persist`.
- `tauri-plugin-sql` не использовать: вся логика в Rust, sqlx и доступ из JS не нужны.

### TD-09. Импортированное аудио копируется в каталог задания — **Принято** (Q-07, Q-15)
- **Почему:**
  - Повторный запуск работает, даже если пользователь переместил исходник.
  - Удаление записи удаляет всё связанное.
  - Оригинал пользователя никогда не изменяется и не удаляется.
- **Цена:** место на диске. Около 30–60 МБ на час MP3 [Оценка]; 6 файлов в день — около 0,2–0,4 ГБ в день. Нужна видимость занятого места и удаление записей.
- **Видео MP4/MOV — принято (Q-15):** видеофайл не копировать (час видео — гигабайты). При импорте движок извлекает аудиодорожку и сохраняет `source.wav` (16 кГц, моно, 16 бит, около 115 МБ на час [Оценка]) — команда `tolk-engine extract`. Повтор и удаление работают так же, как для аудио.

### TD-10. Очередь — **Принято**
- Состояния: `QUEUED → PROCESSING → COMPLETED | FAILED | CANCELLED`. Из `FAILED` и `CANCELLED` задание можно повторить (→ `QUEUED`).
- Один исполнитель. Задание захватывается атомарно: `UPDATE … SET status='PROCESSING' WHERE id=? AND status='QUEUED'`. Это защищает от двойного запуска.
- Второй экземпляр приложения блокирует `tauri-plugin-single-instance`.
- **Восстановление при старте:** `PROCESSING → FAILED` с причиной «Обработка прервана», затем пользователь нажимает «Повторить».
  - Автоматически не перезапускать: если причиной был OOM, перезапуск зациклит сбой.
- Во время обработки система не должна уходить в сон (P1). Предупреждение показывается, если ноутбук работает от батареи (P2).

### TD-11. Редактирование транскрипта посегментно — **Принято** (Q-08)
- **Как:** каждый сегмент редактируется как отдельный абзац.
- **Почему:** таймкоды остаются корректными для экспорта, проще сохранение и защита от потери.
- **Ограничение:** объединение и разбиение сегментов — P2.
- **Отклонённая альтернатива:** редактор всего текста одним полем. Он проще в UI, но после правок таймкоды теряются.

### TD-13. Модели: загрузка из приложения из доверенных источников по согласию, проверка SHA-256, импорт из файла — **Принято** (Q-06)
- **Каталог моделей встроен в приложение.** Пользователь не вводит произвольные URL. Для каждой модели в каталоге:
  - название и версия;
  - источник — человекочитаемо, например «Hugging Face: ggerganov/whisper.cpp», и точный URL;
  - размер, SHA-256, лицензия, ориентировочные требования к RAM.
- **Версия = закреплённая ревизия.** URL ссылаются на конкретный коммит репозитория (`/resolve/<commit>/<file>`), а не на `main`. Поэтому файл по ссылке не может незаметно смениться, а SHA-256 и версия всегда соответствуют друг другу.
- **Перед загрузкой** пользователь видит название, версию, размер и источник. Загрузка начинается только после подтверждения; автоматической загрузки нет.
- **Загрузка:**
  - докачка через `Range`;
  - на каждую попытку берётся новый URL `resolve`, потому что подписанные ссылки CDN истекают;
  - SHA-256 проверяется потоково;
  - установка атомарная: `.part` → `rename`;
  - кнопка «Повторить» после ошибки.
- **Сетевые ограничения.** Корпоративный прокси не требуется: если в ОС настроен системный прокси, он используется автоматически. Если загрузка недоступна (DNS, таймаут, TLS, HTTP 403/5xx), показывается понятная ошибка с предложением импортировать модель из локального файла.

  **Что фактически умеет выбранная конфигурация (MVP-023, проверено чтением исходников `reqwest` 0.13.5 и `hyper-util` 0.1.21; `native-tls` сам по себе прокси не определяет, это делает feature `system-proxy`):**
  - переменные окружения `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` и `NO_PROXY` читаются на всех ОС и имеют приоритет;
  - macOS: настройки системы читаются через SCDynamicStore, **только вручную заданные прокси HTTP и HTTPS** (хост и порт). Список исключений ОС (`ExceptionsList`) не учитывается;
  - Windows: реестр `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`, значения `ProxyEnable`, `ProxyServer`, `ProxyOverride`, также только ручной прокси. Как разбирается строка вида `http=host:port;https=host:port` [Неизвестно, проверить на машине с таким прокси];
  - **не поддерживаются:** автоконфигурация (PAC, `AutoConfigURL`), автообнаружение WPAD, SOCKS, имя и пароль прокси из настроек ОС.
  - **Подтверждено тестами на macOS** (локальный прокси, `crates/core/tests/download_proxy.rs`): прокси из окружения используется, `NO_PROXY` обходит его, `system_proxy = false` его игнорирует, ответ 407 даёт понятную ошибку с предложением импорта. Это проверено для HTTP-цели; HTTPS через туннель `CONNECT` в тестах не воспроизводился.
  - **Не подтверждено:** чтение настроек ОС (SCDynamicStore и реестр) на практике. На этом Mac прокси не настроен, менять системные настройки для проверки нельзя, Windows-машины нет. До проверки считать «заявлено библиотекой, не проверено нами».
  - **Минимальное решение без усложнения:** автоматическое определение оставляем как есть (окружение и ручной прокси ОС), PAC, WPAD, ввод учётных данных и экран настройки прокси не реализуем (Q-06: «корпоративный прокси не требуется»). Любая сетевая ошибка (прокси, TLS, DNS, 403, 407, тайм-аут) превращается в понятное сообщение с предложением импортировать модель из файла. Диагностика: `cargo run -p tolk-core --example net_check` (запрос одного байта по адресам каталога), в UI позже — кнопка «Проверить соединение» на `check_connection`. Если на пилоте выяснится, что у сотрудников прокси задаётся через PAC, запасной вариант — поле «адрес прокси» в настройках (`DownloadConfig`), примерно десяток строк; без PAC-интерпретатора.
- **Импорт из локального файла** (флешка, файл от коллеги) — с той же проверкой SHA-256 по каталогу. Неизвестный файл не устанавливается.
- **Офлайн-гарантия:** после установки модели распознавание полностью работает без сети; при транскрибации модели не скачиваются.
- **Лицензии:** перед релизом проверяются лицензии и право распространения каждого файла из каталога (MVP-029).
- **Позже (не MVP):** настраиваемое зеркало.

### TD-14. Рекомендация модели по RAM — **После бенчмарка**

**Правило (Q-14).** Минимальные системные требования и пороги выбора моделей фиксируются **только по измерениям**. Для каждой конфигурации (ОС × класс RAM × CPU/GPU) измеряются:

- время распознавания;
- пиковая RAM;
- стабильность;
- качество.

До измерения конфигурация считается **непроверенной**: приложение на ней работает, рекомендация модели — предварительная, производительность не обещается.

Отсутствие слабых машин не блокирует разработку прототипа, но блокирует подтверждение совместимости и фиксацию требований для этих конфигураций (MVP-038).

Предварительная стратегия; пороги **не утверждены**:

| RAM | Предварительная рекомендация | Что проверить |
|---|---|---|
| 8 ГБ | turbo q5_0 на CPU/Metal, с предупреждением при нехватке свободной памяти. Запасные варианты: medium q5_0, small q5_1, GigaAM v3. | Пиковая память с открытым браузером и Office; скорость на 4-ядерном CPU |
| 16 ГБ | turbo q5_0 (по умолчанию) | Разница качества q5_0 и q8_0 |
| 24 ГБ | turbo q5_0 или q8_0; f16 — только если даёт измеримый прирост | Прирост качества против времени |

Перед стартом задания сравнивается доступная память с измеренной потребностью модели плюс запас. При нехватке показывается предупреждение, но запуск не запрещается.

**Реализация (MVP-022, 2026-10-18).** Каталог — `crates/core/catalog/models.json`, адреса закреплены на коммит репозитория (TD-13). Объём памяти определяется крейтом `sysinfo` (MIT, только модуль системной информации, без процессов и дисков): своей реализации для двух ОС не пишем. На macOS «доступная память» приблизительна (сжатая и unified-память, риск из MVP-024). Классы памяти делятся серединой между номиналами (до 12 ГиБ — «8 ГБ», до 20 ГиБ — «16 ГБ», выше — «24 ГБ»): эти границы тоже предварительные.

### TD-15. Приватность и сеть — **Принято**
- Нет updater-плагина (автообновлений нет в MVP), телеметрии, аналитики и внешних шрифтов или CDN во фронтенде.
- Задан строгий CSP: `default-src 'self'`, удалённые источники запрещены.
- Единственное сетевое обращение приложения — загрузка модели по действию пользователя.
- Поведение WebView2 (обновления Evergreen-рантайма, SmartScreen-проверки) документируется. В wry проверка SmartScreen отключена по умолчанию [Факт].
- Отсутствие других обращений проверяется брандмауэром на обеих ОС. До этой проверки приложение **не заявляется** как полностью офлайн.

### TD-16. Упрощённая поставка MVP без покупки сертификатов — **Принято** (Q-03, Q-04, Q-05)
- **Общие правила:**
  - сертификаты подписи кода в MVP не приобретаются;
  - нотаризации, автообновлений и централизованного корпоративного развёртывания нет;
  - в установщик входит всё, что нужно приложению: WebView2-рантайм для Windows, движок, VAD-модель;
  - модели распознавания ставятся отдельно через интерфейс приложения (TD-13);
  - подпись, нотаризация и автообновления рассматриваются отдельно перед релизом, если понадобятся.
- **Windows (10 22H2+ / 11, x64):**
  - NSIS `-setup.exe` в режиме `currentUser`, без прав администратора. MSI не делаем.
  - WebView2 — режим `offlineInstaller`: установщик содержит рантайм и ставит его только при отсутствии. Это +~127 МБ к установщику [Факт], зато не нужен интернет при установке.
  - Статический CRT, без зависимости от VC++ Redistributable; без зависимости от `vulkan-1.dll` при старте.
  - Предупреждение SmartScreen («Неизвестный издатель») допустимо и описывается в инструкции как штатный диалог Windows.
- **macOS (13+, Apple Silicon):**
  - `.dmg` с `.app` для arm64.
  - Ad-hoc подпись (`signingIdentity: "-"`) — это не сертификат и не покупка: Apple Silicon не запускает код без подписи вообще [Факт].
  - Первый запуск — через штатный путь macOS: «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть». Точный текст диалога на macOS 13–15 фиксируется в MVP-030.
- **Запрещено:**
  - инструкции по отключению Gatekeeper, SmartScreen или антивируса;
  - снятие атрибута карантина (`xattr`);
  - любые обходы корпоративных политик.

  Если антивирус блокирует сборку, это дефект: разбираемся (ложное срабатывание отправляется вендору антивируса через его официальную форму), но не обходим.
- **Сборка:** на каждой ОС отдельно (GitHub Actions `windows-latest`, `macos-15`), без кросс-компиляции.
- **Проверка на чистой системе без инструментов разработки:** Windows VM (H6) и Mac без Xcode/Homebrew.

### TD-17. Фронтенд: Svelte + TypeScript + Vite — **Принято** (Q-11)
- **Основа:** Svelte 5 (runes) + TypeScript + Vite, **без SvelteKit**. Одностраничное приложение: экраны переключаются состоянием, роутер не нужен, SSR и адаптеры не нужны.
- **Зависимости:**
  - `@tauri-apps/api`;
  - плагины Tauri (dialog, single-instance).
  
  UI-китов, state-менеджеров, CSS-фреймворков и библиотек форм нет. Новая зависимость добавляется только под конкретную подтверждённую потребность, с записью причины в этот документ.
- **Очередь и прогресс:**
  - реактивное состояние Svelte (`$state`) хранит список заданий;
  - прогресс приходит из Rust через `Channel` и обновляет состояние;
  - источник истины — Rust и БД: после перезапуска UI просто запрашивает список.
- **React не используется:** технического преимущества для этой задачи не выявлено.
- **Сетевой клиент для загрузки моделей (MVP-023, решение владельца 2026-10-18):** `reqwest` версии `=0.13.5`, `default-features = false`, features `native-tls`, `system-proxy`, `blocking`. Причины: системное хранилище сертификатов (корпоративные центры сертификации: SecureTransport на macOS, Schannel на Windows), поддержка корпоративных сетей, `tokio` допустим как транзитивная зависимость (его и так использует Tauri). Особенности версии 0.13: набор по умолчанию уже не `native-tls`, а `rustls` с платформенной проверкой сертификатов; поэтому `default-features = false` обязателен, иначе в сборку попадёт второй TLS-стек (`rustls` в графе зависимостей отсутствует, проверено `cargo tree`). Версия закреплена точно: поведение прокси и TLS не должно меняться незаметно при обновлении. Одновременно добавлены `sha2` 0.10 (потоковая SHA-256, уже была в графе через Tauri), `fs4` 1 (свободное место на диске, MIT/Apache) и `sysinfo` 0.39 (память, TD-14). `cargo deny check licenses bans sources` проходит.
- **Версии и раскладка каркаса (MVP-012, 2026-10-18):** Vite 8, Svelte 5.57, TypeScript 6 (`svelte-check` 4.7 не поддерживает TypeScript 7), менеджер пакетов npm. Фронтенд в `app/`, Rust-часть в `app/src-tauri` (крейт `tolk-app`). Идентификатор приложения — `kg.devcats.tolk` (на macOS каталог данных — `~/Library/Application Support/kg.devcats.tolk`): смена идентификатора после выпуска оставит пользователей без данных, поэтому его нужно подтвердить владельцем до пилота.

### TD-18. Персональный словарь терминов — **Принято** (Q-12); способ применения — **После бенчмарка**
- **Что это:** локальный список названий систем и продуктов, имён, аббревиатур и специфических терминов пользователя.
- **Формат записи:**
  - **термин** — каноническое написание, например «Kubernetes»;
  - **варианты** — как термин может быть распознан или написан иначе, например «кубернетес», «кубер»; необязательное поле;
  - **заметка** — необязательное поле;
  - **флаг «активен»** — неактивные термины не используются при распознавании.
- **Хранение:** таблица `glossary_terms` в SQLite. Это метаданные, а не аудио, поэтому соответствует TD-08.
- **Обмен без сервера:**
  - **Экспорт** — в файл `*.tolk-glossary.json` с полями `format`, `version`, `exported_at`, `terms[]`.
  - **Импорт** — слияние со своим словарём:
    - совпадение терминов определяется после нормализации (регистр, `ё→е`, пробелы);
    - варианты совпавших терминов объединяются;
    - после импорта показывается сводка «добавлено / объединено / пропущено».
  - Импортируемый файл — недоверенные данные: строгая проверка схемы, ограничения размера и длины полей.
- **Применение при распознавании** (способ выбирается по замерам MVP-037):
  1. **Подсказка движку:**
     - **Whisper:** `initial_prompt` вида «Термины: …» [Факт: параметр есть в `whisper_full_params`]. Подсказка повторяется для каждого окна через `carry_initial_prompt` — нужна версия whisper.cpp, где параметр есть [Факт по исходникам master; проверить в выбранной привязке, TD-05].
       - Ограничение: подсказка Whisper — до ~224 токенов (половина текстового контекста) [Оценка по архитектуре Whisper; проверить в whisper.cpp]. Кириллица в токенизаторе Whisper дорогая, поэтому в подсказку помещается порядка десятков терминов [Оценка]. Если активных терминов больше, UI предупреждает, сколько из них не войдёт.
     - **GigaAM (если выбран):** hotwords в sherpa-onnx для transducer-моделей [Оценка: проверить поддержку для GigaAM RNNT]; для CTC подсказки нет.
  2. **Осторожная постобработка:**
     - Замена выполняется **только** по явно заданным пользователем вариантам: целое слово, без учёта регистра, с границами слов для кириллицы.
     - Нечёткого автоисправления (fuzzy) в MVP нет: велик риск ложных замен.
     - `original.json` всегда остаётся сырым выводом движка. Замены применяются при создании `transcript.json`, а «Вернуть исходный текст» их откатывает.
- **Без гарантий:** приложение не обещает исправить все термины. Эффективность измеряется на тестовых записях (BENCHMARK_PLAN, метрика «точность терминов»).
- **Известный риск подсказки Whisper:** текст подсказки может «протекать» в вывод на тишине и усиливать галлюцинации [Оценка, известное поведение Whisper]. Поэтому подсказка включается по умолчанию, только если замеры показали, что WER не ухудшается и галлюцинаций на A4 не прибавилось.

## 6. Вне MVP (сознательно исключено)

- Разделение по спикерам (диаризация).
- Запись с микрофона.
- Подпись кода, нотаризация, автообновление — рассматриваются отдельно перед релизом.
- Централизованное корпоративное развёртывание (MSI, Intune, GPO).
- Суммаризация и LLM.
- Перевод.
- Синхронизация и облако.
- Центральный сервер словарей.
- Linux, Windows ARM; Intel Mac и специальная поддержка слабых ПК — отдельным этапом после MVP (Q-13).
- CUDA, Core ML.
- Параллельная обработка нескольких файлов.
- Воспроизведение аудио с подсветкой сегмента (кандидат P2 после MVP).
- Поиск по истории.
- Нечёткое автоисправление терминов.
- Декодирование видеопотока; кодеки HE-AAC, AC-3, AMR, WMA (кроме случая, когда MVP-035 покажет необходимость — TD-07).
