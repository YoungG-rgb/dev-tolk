## 2. Что нужно сообщить о каждой другой машине

Для каждой машины, на которой можно будет запускать замеры или проверять сборки:

1. **Кто владелец и когда доступна**: постоянно, только по договорённости, только для разовой проверки. Можно ли ставить инструменты разработки (Rust, Visual Studio Build Tools, CMake, LLVM, Vulkan SDK) или только запускать готовые сборки.
2. **CPU**: модель и число физических ядер.
3. **GPU**: модель и версия драйвера; встроенная или дискретная.
4. **RAM**: объём (и сколько обычно занято фоновыми программами).
5. **ОС**: версия и сборка (для Windows важно: 10 22H2 или 11; редакция Home/Pro).
6. **Диск**: SSD или HDD, свободное место (нужно не меньше ~10 ГБ).
7. **Режим питания**: ноутбук или стационарный, можно ли держать на сети питания во время прогона.
8. **Сеть**: есть ли ограничения (прокси, блокировка `huggingface.co` и `*.hf.co`) — влияет на проверку загрузки моделей (R-07).
9. **Политики безопасности**: антивирус или корпоративные политики, запрещающие неподписанные программы (R-06).
10. Для Windows-ПК отдельно: поддерживается ли **Windows Sandbox** или **Hyper-V** (нужна редакция Pro/Enterprise/Education [Оценка: проверить] и включённая виртуализация) — это замена отдельной чистой машине H6 (блокер B-4). Виртуальная машина на этом Mac не подходит: она запустит Windows ARM, а не x64.

### Как собрать сведения

**macOS** (проверено на H2):

```bash
system_profiler SPHardwareDataType SPDisplaysDataType SPStorageDataType | grep -E "Model|Chip|Memory|Cores|Medium Type|Free:"
sw_vers
pmset -g batt | head -1
```

**Windows** (PowerShell; команды стандартные, на Windows не запускались):

```powershell
Get-CimInstance Win32_Processor | Select Name, NumberOfCores, NumberOfLogicalProcessors
Get-CimInstance Win32_VideoController | Select Name, DriverVersion
Get-CimInstance Win32_ComputerSystem | Select @{n='RAM_GB';e={[math]::Round($_.TotalPhysicalMemory/1GB,1)}}
Get-ComputerInfo | Select OsName, OsVersion, WindowsEditionId
Get-PhysicalDisk | Select MediaType, Size
```

Достаточно прислать вывод. Серийные номера и имена учётных записей присылать не нужно.

## 4. Подключение CI к удалённому репозиторию

Сейчас: локальный репозиторий, ветка `main`, 7 коммитов, без удалённого репозитория; workflow `.github/workflows/ci.yml` написан и **ни разу не запускался**.

Что нужно от вас:

1. **Платформа.** План рассчитан на GitHub Actions (`windows-latest`, `macos-15`). Если в компании другая платформа или есть ограничения на размещение кода во внешних сервисах, нужен аналог, и workflow придётся переписать.
2. **Пустой удалённый репозиторий** (без README и лицензии, чтобы не было конфликта первой отправки). Приватный или публичный — на ваше усмотрение; код не содержит записей, моделей и секретов (проверено на текущей истории). Для частных репозиториев минуты Actions тарифицируются, macOS-раннеры дороже Linux и Windows [Оценка: проверить в тарифе].
3. **URL репозитория.** После этого я добавлю `origin`; **отправку (`git push`) выполню только после вашего прямого разрешения**.
4. **Включённые Actions** в настройках репозитория.
5. **Секреты не нужны**: сборки неподписанные (TD-16).

Что произойдёт после первой отправки и чего ожидать:

- запустятся две задачи на каждой ОС: ядро и движок (fmt, clippy, сборка, тесты), приложение (проверка фронтенда, сборка `.app` и `.exe` NSIS);
- на Windows код ещё не компилировался: возможны ошибки (сборка libopus через MSVC, пути, тест занятого файла `file_locked_by_another_handle_gives_clear_busy_error`). Это ожидаемо; исправления войдут в MVP-003, MVP-008, MVP-012, MVP-015;
- результаты CI закроют критерий «зелёный CI» MVP-003 и часть Windows-проверок других задач. Остальное (установка на чистой Windows, SmartScreen) CI не заменит.

Что не нужно: GitHub CLI на этом Mac (`gh` не установлен). Если вы предпочитаете создать репозиторий через него, `brew install gh` и `gh auth login` выполняете вы: учётные данные не передаются мне.
