То есть на неформальной речи `small` заметно хуже, а turbo близок к полной large-v3 (для TD-02: малая выборка, один говорящий-короткие реплики, без эталона). ### [~] MVP-017. Запрет сна системы во время обработки

  - **Ограничения:** имя запрета в `pmset` у `keepawake` 0.6 пустое (причина не передаётся), экран может гаснуть; закрытая крышка ноутбука всё равно усыпит систему, это описывается в инструкции (MVP-033).

### [~] MVP-038. Замеры на устройствах сотрудников и фиксация системных требований
- **Цель:** подтвердить совместимость и зафиксировать системные требования только по измерениям (Q-14, TD-14).
- **Результат:**
  - в приложении для каждого задания локально сохраняются: длительность записи, время обработки, пиковая память движка, бэкенд (Metal/Vulkan/CPU), модель, результат (успех или код ошибки). Данные берутся из события `done` (MVP-009);
  - кнопка «Сохранить отчёт о производительности» создаёт файл. В файле:
    - есть: ОС, CPU, RAM, метрики заданий;
    - **нет:** текста транскриптов и имён файлов.
    
    Сотрудник передаёт файл вручную, сетевой отправки нет;
  - замеры на реальных устройствах сотрудников или временно доступных компьютерах, по каждой встреченной конфигурации (ОС × класс RAM × CPU/GPU):
    - время распознавания;
    - пиковая RAM;
    - стабильность — сбои за неделю работы;
    - качество — оценка пользователя 1–5 и выборочная проверка 5 минут текста;
  - `docs/SYSTEM_REQUIREMENTS.md`: таблица конфигураций со статусом «проверено / ограниченно / не проверено» и рекомендуемой моделью; итоговые пороги в TD-14.
- **Критерии приёмки:**
  - системные требования содержат только измеренные конфигурации; остальные явно помечены «не проверено», производительность для них не обещается;
  - для каждого класса RAM, который есть у сотрудников (8 / 16 / 24 ГБ), есть хотя бы одно измерение — или явная пометка, что устройств этого класса не нашлось;
  - отчёт о производительности не содержит текстов и имён файлов (проверка на образце).
- **Зависимости:** MVP-030, MVP-031, MVP-025
- **Приоритет / размер:** P0 / M
- **Риски:** у сотрудников может не оказаться части конфигураций; замеры на рабочих машинах шумные из-за фоновых программ. Фиксировать условия и не делать выводов по одному прогону.
- **Проверки:** сверка метрик приложения с внешним замером (`/usr/bin/time -l`, Process Explorer) на H2 и одной Windows-машине: расхождение ≤ 10%.
- **Прогресс (2026-10-18), только хранение и файл отчёта:** миграция v3 (`job_metrics`) и модуль `metrics` в `crates/core`: `record` (длительность записи, время обработки, пиковая память, бэкенд `metal`/`vulkan`/`cpu`, модель, результат `SUCCESS`/`FAILED`/`CANCELLED`, код ошибки; повтор заменяет прежнюю запись), `set_rating` (оценка пользователя 1–5), `build_report` и `save_report` (атомарная запись, ОС и её версия, архитектура, CPU, число ядер, RAM, AVX2; по каждому заданию длительность, время, RTF, пиковая RAM, бэкенд, модель, результат, оценка; сводка по (модель, бэкенд): число заданий, успешные, медиана и максимум RTF по успешным, максимум памяти). Метрики не привязаны внешним ключом к заданиям и остаются после удаления записи: содержимого в них нет. 10 тестов проходят на macOS, в том числе проверка приватности: в файле нет имён файлов, текстов транскриптов, идентификаторов заданий, путей, имени пользователя и имени компьютера. Миграция настоящей базы v2 → v3 проверена запуском собранного `.app`.
  - **Источник данных и интерфейс (2026-10-18):** метрики записывает исполнитель очереди после каждого задания (длительность записи, время обработки, пиковая память из события `done`, бэкенд, модель, результат и код ошибки). На вкладке «Диагностика» кнопка «Сохранить отчёт о производительности…» (диалог сохранения, имя `dev-tolk-отчёт-ГГГГ-ММ-ДД.json`, пояснение, что именно попадает в файл и что приложение ничего не отправляет). В списке записей у готовых заданий оценка качества 1–5 (звёзды), она попадает в отчёт.
  - **Проверено в окне собранного `.app` на H2 (macOS 15.3, Apple M4, 24 ГБ):** задание с приметным именем файла (`ZZ-Конфиденциальная-запись-Иванов.ogg`) обработано turbo; оценка 4 сохранена и видна после обновления списка; отчёт содержит формат `tolk-performance-report` v1, ОС, ЦП, ОЗУ, строку задания (RTF 0,108, пик 779 МБ, бэкенд `metal`, оценка 4) и сводку по (модель, бэкенд); **ни имени файла, ни слов расшифровки (19 слов 5+ букв) в отчёте нет** (проверка на образце); **сверка с внешним замером**: пик памяти в отчёте 779–780 МБ, `/usr/bin/time -l` тем же движком на том же файле 776–782 МБ, расхождение 0,4–0,6% (критерий ≤ 10%).
  - **Не сделано:** `docs/SYSTEM_REQUIREMENTS.md` и замеры на реальных компьютерах сотрудников (MVP-030/031, пилот); сверка на Windows (Process Explorer; на Windows `peak_rss_bytes` не реализован); оценка качества показывается только в списке (не после обработки сразу); стабильность за неделю не измерялась; классы RAM 8 и 16 ГБ не измерялись (устройств нет).
