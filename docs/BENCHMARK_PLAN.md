## 1. Цели

Испытания должны ответить на вопросы:

1. Даёт ли выбранный движок приемлемое качество русского текста на **наших** записях длиной 30–60 минут?
2. Сколько времени и пиковой памяти занимает обработка часа записи на целевых машинах: 8 / 16 / 24 ГБ, Windows и macOS?
3. Какую модель рекомендовать для каждого класса RAM (TD-14)?
4. Стоит ли GPU-ускорение на Windows (Vulkan) своей сложности?
5. Превосходит ли GigaAM v3 или Parakeet v3 Whisper turbo настолько, чтобы сменить движок (TD-03)?
6. Устойчив ли движок к ошибкам: битый файл, отмена, нехватка памяти, кириллица в путях?
7. Помогает ли словарь терминов (подсказка движку и постобработка) и не ухудшает ли он общий текст?

## 2. Тестовый корпус (MVP-002)

### 2.1 Записи

| ID | Описание | Длительность | Формат | Зачем |
|---|---|---|---|---|
| A1 | Совещание, 3–6 человек, микрофон ноутбука или конференц-спикер | ~60 мин | M4A (AAC-LC) | Основной сценарий |
| A2 | Совещание или интервью, 2 человека, хорошее качество | ~45 мин | MP3 128 кбит/с | Основной сценарий |
| A3 | Диктофон телефона в помещении с эхом и шумом | ~30 мин | M4A | Сложное аудио |
| A4 | Запись с длинными паузами (>1 мин), музыкой или фоном | ~30–40 мин | MP3 | Проверка галлюцинаций в тишине |
| A5 | Речь с терминами, аббревиатурами, числами и английскими вставками | ~30 мин | MP3 или M4A | Предметная лексика |
| A6 | Голосовое из мессенджера (OGG/Opus) | 1–5 мин | OGG | Проверка формата |

Требования:

- Записи используются только с согласия участников (Q-16).
- Образцы форматов (видео MP4/MOV, разные мессенджеры и диктофоны) собираются отдельно в MVP-035. Для качества распознавания они не нужны.
- Корпус хранится локально у разработчика и не коммитится в репозиторий.
- Фиксируются SHA-256 каждого файла, чтобы все замеры шли на одних и тех же данных.

### 2.2 Эталон для WER/CER

- Из A1, A2, A3 и A5 вырезаются по 5 минут: всего 20 минут эталона, 4 фрагмента.
- **Как готовится эталон (Q-12).** Эталон делается отдельно от оценки:
  1. Фрагмент распознаётся моделью-черновиком.
  2. Человек прослушивает фрагмент целиком и вручную исправляет каждое слово, включая термины.
  3. Второй человек (или тот же через день) повторно прослушивает и сверяет.
- **Смещение эталона.** Эталон, исправленный из черновика модели X, систематически занижает WER модели X: мелкие ошибки, похожие на правду, легче пропустить. Меры:
  - черновик делать моделью, которая **не** участвует в сравнении как кандидат по умолчанию — например, `ggml-large-v3` (полная, не turbo);
  - в отчёте указывать модель черновика;
  - при близких результатах кандидатов (разница < 1 п.п.) смещение считать возможной причиной и не делать вывода о превосходстве.
- **Нормализация перед сравнением** (одинаково для всех систем):
  - нижний регистр;
  - `ё → е`;
  - удаление пунктуации;
  - схлопывание пробелов;
  - числа в одном виде — либо словами, либо цифрами, правило фиксируется в отчёте;
  - междометия («э-э», «ну») исключаются из обоих текстов.
- Метрики считаются на машине разработчика скриптом (например, `jiwer`). Python на машинах сотрудников не нужен.

### 2.3 Файлы для проверки ошибок

- MP3, обрезанный на середине.
- Файл с расширением `.mp3`, но внутри текст.
- M4A с HE-AAC (если удастся найти).
- WAV 8 кГц.
- Файл 0 байт.
- Очень короткий файл (2 секунды).
- Путь с кириллицей и пробелами: `C:\Users\Иван Петров\Записи\совещание 1.mp3`.
- Модель в каталоге пользователя с кириллицей в имени (Windows).

### 2.4 Тестовый словарь терминов (для MVP-004 W9 и MVP-037)

- 20–40 реальных терминов из записей A1–A5 (особенно A5): названия систем и продуктов, имена, аббревиатуры. У каждого — каноническое написание и 1–3 варианта.
- Каждый термин встречается в эталонных фрагментах хотя бы один раз. Для каждого вхождения в эталоне размечается позиция.
- Добавить 5 «ловушек»: термины, которых нет в записях. Они нужны, чтобы ловить ложные вставки из подсказки.

Для каждой машины фиксируются:

- модель CPU и число физических ядер;
- GPU и версия драйвера;
- объём RAM;
- свободное место на диске;
- тип диска (SSD/HDD);
- версия ОС;
- режим питания.

**Правило доступности (Q-14).**

- Используются только компьютеры, которые уже есть в команде. Устройства ради бенчмарков не покупаются и не арендуются.
- Если машины какого-то класса нет, строки результатов помечаются «не измерено», а конфигурация — «непроверенная». Выводы по этому классу не делаются, системные требования для него не фиксируются, производительность не обещается.
- Отсутствие слабых машин **не блокирует** прототип и разработку. Подтверждение совместимости этих классов переносится на замеры на устройствах сотрудников (MVP-038, §9).

## 5. Методика

### 5.1 Условия прогона

- Ноутбук подключён к сети питания, режим питания «сбалансированный» (фиксируется).
- Закрыты тяжёлые приложения. Для класса 8 ГБ дополнительно делается прогон W1 «в реальных условиях»: открыт браузер с 10 вкладками и Word/Excel.
- Первый прогон после перезагрузки записывается как «холодный», затем «тёплый».
- **H2 — MacBook Air без вентилятора.** При длительной нагрузке частоты снижаются (троттлинг) [Оценка]. Поэтому:
  - между 60-минутными прогонами делать паузу 10 минут;
  - фиксировать время прогона по четвертям: прогресс 25/50/75/100% с отметкой времени;
  - отдельно записать время обработки очереди из 3 записей подряд — это реальный сценарий дня.
- Число потоков CPU на H2: прогоны с 4 потоками (только производительные ядра) и с потоками по умолчанию; в отчёт — лучший вариант.
- Основная конфигурация (W1 и победитель G/P) прогоняется на A1 **дважды**, остальные — по одному разу на каждой записи. Если результаты двух прогонов расходятся больше чем на 10%, делается третий прогон и записывается медиана.

### 5.2 Метрики

| Метрика | Как измерять |
|---|---|
| Время обработки (wall clock) | macOS: `/usr/bin/time -l <cmd>`. Windows: `Measure-Command` в PowerShell. Включает загрузку модели и декодирование |
| RTF | время обработки / длительность записи |
| Пиковая память | macOS: `/usr/bin/time -l` — строки «maximum resident set size» **и** «peak memory footprint». На Apple Silicon память Metal — общая (unified), поэтому ориентироваться на footprint. Windows: PowerShell-скрипт, который запускает процесс и раз в 250 мс опрашивает `PeakWorkingSet64` и `PeakPagedMemorySize64`, либо Process Explorer → Peak Private Bytes |
| WER / CER | по эталону (§2.2), отдельно для каждого фрагмента и среднее |
| Галлюцинации и повторы | (1) число повторяющихся подряд n-грамм (n ≥ 4, ≥ 3 повтора) по всему тексту; (2) текст, распознанный на участках тишины A4; (3) ручной просмотр трёх случайных 2-минутных окон на каждую запись |
| Пунктуация и читаемость | Экспертная оценка 1–5 двумя людьми вслепую (тексты систем перемешаны) на фрагментах эталона |
| Таймкоды | Есть / нет; выборочная проверка 10 сегментов: расхождение начала ≤ 1 с |
| Точность терминов (W9, MVP-037) | По тестовому словарю (§2.4): доля вхождений терминов из эталона, распознанных в каноническом написании (без учёта регистра); число ложных вставок терминов, включая «ловушки»; WER и повторы на A4 — с подсказкой и без |
| Нагрев и троттлинг | Частота CPU в конце прогона (Mac: `powermetrics`, по возможности) — только как наблюдение |

### 5.4 Проверки устойчивости (MVP-011)

| Проверка | Ожидаемое поведение |
|---|---|
| Принудительное завершение процесса движка на середине | Нет незавершённого файла результата под итоговым именем (только временный); повторный запуск работает |
| Битый, пустой и «не аудио» файл | Понятная ошибка (код возврата и сообщение), без panic-трассы и без зависания |
| HE-AAC M4A | Либо корректный текст, либо понятная ошибка «формат не поддерживается» |
| Отсутствует или повреждён файл модели | Понятная ошибка до начала декодирования |
| Кириллица и пробелы в путях к аудио и модели (Windows) | Работает |
| Запуск на H6 (без драйвера GPU и VC++ Redistributable) | Процесс стартует; при отсутствии Vulkan происходит откат на CPU или выдаётся понятная ошибка |
| Нехватка памяти (8 ГБ + нагрузка) | Фиксируем фактическое поведение: своп, замедление, падение. Это влияет на предупреждение о памяти (TD-14) |
| Сеть отключена | Транскрибация работает полностью |

## 6. Критерии решения (приняты владельцем продукта 2026-10-18 — Q-10)

Ежедневная нагрузка — 5–6 записей по 30–60 минут, то есть до ~6 часов аудио в день на машину. Пороги применяются только к измеренным конфигурациям:

| Критерий | Порог | Обоснование |
|---|---|---|
| Время на 8 ГБ, Windows, CPU | RTF ≤ 0,5: 60 минут обрабатываются ≤ 30 минут | Дневная нагрузка укладывается в ≤ 3 ч фоновой обработки |
| Время на 16+ ГБ и Apple Silicon | RTF ≤ 0,25 | Пользователь ждёт результат не дольше 15 мин на час записи |
| Пиковая память на 8 ГБ | ≤ 3 ГБ footprint/private | Остаётся память на ОС, браузер и Office |
| Качество | WER не хуже лучшего кандидата + 2 п.п.; нет зацикливаний на A1–A5 при включённом VAD | Качество важнее скорости, но зацикливание недопустимо |
| Устойчивость | Все проверки §5.4 пройдены | — |

Правила выбора:

- Если на 8 ГБ ни одна конфигурация Whisper не проходит пороги, а GigaAM проходит — GigaAM рассматривается как модель по умолчанию для 8 ГБ, либо как единственный движок (решение в MVP-007).
- Если ни один движок не проходит пороги на 8 ГБ — пороги пересматриваются с владельцем продукта (Q-10), либо машины 8 ГБ объявляются «ограниченно поддерживаемыми».
- Если машин на 8 ГБ в команде нет — правила выше применяются позже, по данным MVP-038. До этого рекомендация для 8 ГБ предварительная.

## 9. Замеры на устройствах сотрудников (MVP-038)

Выполняются на релиз-кандидате, без инструментов разработчика на машинах сотрудников.

1. Приложение само записывает по каждому заданию:
   - длительность записи;
   - время обработки;
   - пиковую память движка;
   - бэкенд;
   - модель;
   - результат.
2. Сотрудник работает обычным образом не меньше недели. Затем нажимает «Сохранить отчёт о производительности» и передаёт файл вручную. Текстов и имён файлов в отчёте нет.
