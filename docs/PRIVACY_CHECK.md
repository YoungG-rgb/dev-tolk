# Сетевые обращения и офлайн-режим (MVP-028): черновик

Состояние на 2026-10-18. **Аудит не выполнен.** Здесь зафиксированы ожидаемые обращения, метод и предварительные наблюдения на каркасе приложения. Приложение **не заявляется** полностью офлайн, пока аудит не пройден на установленных сборках (TD-15).

## 1. Ожидаемые обращения

Единственное осознанное сетевое действие приложения — загрузка модели по явному действию пользователя (TD-13).

| Домен | Зачем | Источник |
|---|---|---|
| `huggingface.co` | адрес модели из каталога (`crates/core/catalog/models.json`), ответ-перенаправление | каталог моделей |
| `us.aws.cdn.hf.co` (в общем случае `*.hf.co`) | CDN, на который перенаправляет `huggingface.co`; наблюдался 2026-10-18 по заголовку `Location` | заголовки ответа |

Для белого списка корпоративного брандмауэра указывать `huggingface.co` и `*.hf.co`; имя CDN может меняться (риск R-07). Загрузчик принимает редиректы только на эти домены и только по HTTPS (`DownloadConfig::production`).

Системные обращения, которые не относятся к приложению и должны фиксироваться отдельно: WebView2 (Evergreen-рантайм, обновления), проверки Gatekeeper и OCSP на macOS, SmartScreen на Windows.

## 2. Метод (план)

- macOS: Little Snitch или LuLu, `nettop` с правами администратора, `lsof -i`.
- Windows: правило брандмауэра с журналированием или `pktmon`, Resource Monitor.
- Сценарии: установка, первый запуск, импорт, транскрибация, редактирование, экспорт, перезапуск.
- Повторный прогон всех сценариев с полностью заблокированной сетью после установки модели.
- Проверять **установленные** сборки (`.dmg`, `.exe`), а не dev-режим: в dev-режиме есть обращения к серверу разработки Vite.

## 3. Предварительные наблюдения (каркас, macOS, 2026-10-18)

Условия: собранный `dev-tolk.app` из `tauri build` (release), H2, macOS 15.3, приложение запущено и бездействует, окно открыто.

| Наблюдение | Результат |
|---|---|
| `lsof -nP -i` для процесса приложения и процессов WebKit (`WebContent`, `Networking`, `GPU`), 4 снимка за 16 секунд | сокетов нет |
| Самопроверка CSP на странице (запрос на `https://csp-check.invalid/`) | заблокирована политикой до сети, событие нарушения получено, результат в журнале |
| `nettop` | не дал данных (нет прав администратора), вывода по процессам нет |

**Что это не доказывает.** Снимки `lsof` каждые 4 секунды пропускают короткие соединения; DNS-запросы (UDP через системный резолвер) могли не отобразиться; интерфейса пока нет, сценарии импорта, транскрибации и экспорта не выполнялись; Windows не проверялся. Результат годится только как отсутствие очевидных постоянных соединений у пустого каркаса.
