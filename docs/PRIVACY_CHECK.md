# Сетевые обращения и офлайн-режим (MVP-028)

Состояние на 2026-10-18. **Аудит выполнен на macOS (H2), на Windows не выполнен.** §1–3: ожидаемые обращения, метод и предварительные наблюдения на каркасе; §4: результаты аудита macOS на собранном приложении; §5: что остаётся.

## 1. Ожидаемые обращения

Единственное осознанное сетевое действие приложения — загрузка модели по явному действию пользователя (TD-13).

| Домен | Зачем | Источник |
|---|---|---|
| `huggingface.co` | адрес модели из каталога (`crates/core/catalog/models.json`), ответ-перенаправление | каталог моделей |
| `us.aws.cdn.hf.co` (в общем случае `*.hf.co`) | CDN, на который перенаправляет `huggingface.co`; наблюдался 2026-10-18 по заголовку `Location` | заголовки ответа |

Для белого списка корпоративного брандмауэра указывать `huggingface.co` и `*.hf.co`; имя CDN может меняться (риск R-07). Загрузчик принимает редиректы только на эти домены и только по HTTPS (`DownloadConfig::production`).

Системные обращения, которые не относятся к приложению и должны фиксироваться отдельно: WebView2 (Evergreen-рантайм, обновления), проверки Gatekeeper и OCSP на macOS, SmartScreen на Windows.

## 2. Метод (план)

- macOS: Little Snitch или LuLu, `nettop` с правами администратора, `lsof -i`.
- Windows: правило брандмауэра с журналированием или `pktmon`, Resource Monitor.
- Сценарии: установка, первый запуск, импорт, транскрибация, редактирование, экспорт, перезапуск.
- Повторный прогон всех сценариев с полностью заблокированной сетью после установки модели.
- Проверять **установленные** сборки (`.dmg`, `.exe`), а не dev-режим: в dev-режиме есть обращения к серверу разработки Vite.

## 3. Предварительные наблюдения (каркас, macOS, 2026-10-18)

Условия: собранный `dev-tolk.app` из `tauri build` (release), H2, macOS 15.3, приложение запущено и бездействует, окно открыто.

| Наблюдение | Результат |
|---|---|
| `lsof -nP -i` для процесса приложения и процессов WebKit (`WebContent`, `Networking`, `GPU`), 4 снимка за 16 секунд | сокетов нет |
| Самопроверка CSP на странице (запрос на `https://csp-check.invalid/`) | заблокирована политикой до сети, событие нарушения получено, результат в журнале |
| `nettop` | не дал данных (нет прав администратора), вывода по процессам нет |

**Что это не доказывает.** Снимки `lsof` каждые 4 секунды пропускают короткие соединения; DNS-запросы (UDP через системный резолвер) могли не отобразиться; интерфейса пока нет, сценарии импорта, транскрибации и экспорта не выполнялись; Windows не проверялся. Результат годится только как отсутствие очевидных постоянных соединений у пустого каркаса.

## 4. Результаты аудита macOS (2026-10-18, H2, macOS 15.3, сборка 0.1.0, `.app` из `tauri build` с feature `ui-test`)

Сборка `ui-test` отличается от выпускной только тем, что позволяет выполнить сценарий в окне; сетевого кода она не добавляет (команды `import_paths`, `model_import_path`, `glossary_import_path` читают локальные файлы).

**Метод.** Права администратора не нужны и системные настройки не менялись. Приложение запускалось под профилем `sandbox-exec` (`tools/ui-test/nonet.sb`: `(deny network*)`), который запрещает процессу и его дочерним процессам (включая `tolk-engine`) любые сетевые вызовы, в том числе localhost и DNS. Контроль профиля: `curl https://huggingface.co/` без профиля даёт HTTP 200, под профилем «Could not resolve host», в журнале ядра `Sandbox: curl deny(1) network-outbound /private/var/run/mDNSResponder`; привязка к `127.0.0.1` из Python под профилем запрещена. Отказы читались из журнала ядра (`/usr/bin/log show`, события `Sandbox ... deny(1) network*`). Отдельно: `lsof -nP -i -a -p <pid>` каждые 30 мс во время загрузки компонента по кнопке (с сетью).

**1. Все сценарии без сети** (`tools/ui-test/run.py` целиком, процесс приложения под профилем без сети): импорт аудио и видео и отказы, очередь из шести записей, отмена и повтор, закрытие окна и `kill -9`, правка и экспорт в DOCX, словарь (экспорт и импорт), «Диагностика» и отчёт, экран «Модели», импорт модели из файла и обработка записи на импортированной модели с моделью определения речи из `.app`: **всё работает, ошибок нет**. Кнопка «Докачать компонент» без сети даёт «Не удалось найти адрес сервера: домен недоступен. Проверьте подключение к сети или импортируйте модель из файла» и предлагает импорт из файла.

**2. Попытки обращений, которые видело ядро за весь прогон (все сценарии, около 10 минут):**

| Процесс | Операция | Что это | Откуда |
|---|---|---|---|
| `tolk-app` | `network-bind` и `network-outbound` на `/private/tmp/kg_devcats_tolk_si.sock` | локальный сокет плагина «один экземпляр» (не интернет) | запуск приложения |
| `tolk-app` | `network-outbound` на `/private/var/run/syslog` | локальный сокет системного журнала (не интернет) | журнал приложения |
| `tolk-app` | `network-outbound` на `/private/var/run/mDNSResponder` (**один раз**) | DNS-запрос | нажатие «Докачать компонент» без сети (явное действие пользователя) |
| `tolk-engine` | — | **ни одной попытки** | |

Других попыток выхода в интернет у процессов приложения и движка нет. Процесс `com.apple.WebKit.Networking` (сетевая служба веб-вида, не процесс приложения и не под профилем) пытался только обратиться к системной службе `com.apple.analyticsd` (`mach-lookup`, не сеть; системная телеметрия WebKit, зависит от настроек macOS, приложением не управляется).

**3. С сетью, загрузка компонента по кнопке** (`lsof` процесса `tolk-app`): удалённые адреса `108.138.51.26:443` (CloudFront; на тот же сегмент `108.138.51.x` указывает `huggingface.co`) и `35.181.67.163:443` (AWS, eu-west-3; вероятно CDN-хост `*.hf.co`: имя по обратному DNS это узел EC2, поэтому домен достоверно не установлен). Только порт 443 (HTTPS), только на время загрузки. Загрузчик принимает адреса и редиректы только на `huggingface.co`, `hf.co` и их поддомены (`DownloadConfig::production`, тесты MVP-023). Файл получен и проверен по SHA-256 (885 098 байт).

**4. Бездействие и запуск.** Во всех запусках до нажатия «Скачать»/«Докачать» соединений `tolk-app` и `tolk-engine` с интернетом не было (отказов нет, кроме п. 2); на чистой установке 3 секунды на мастере: каталог моделей пуст, ничего не скачивается.

### Домены для белого списка корпоративного брандмауэра (macOS-часть подтверждена наблюдением)

`huggingface.co` и `*.hf.co` (порт 443, только на время скачивания модели). Больше ничего приложению не нужно. Системные службы (Apple: проверки Gatekeeper и OCSP при первом запуске, обновления macOS, телеметрия WebKit) к приложению не относятся и в этом аудите не измерялись.
