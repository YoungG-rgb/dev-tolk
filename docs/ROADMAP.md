# Роадмап MVP — dev-tolk

Состояние на 2026-10-18. Решения владельца продукта по Q-01 … Q-16 получены (MVP-001 выполнена). Разработка не начата, измерения не выполнены.

Документы проекта:

- `TASKS.md` — задачи и критерии приёмки;
- `TECHNICAL_DECISIONS.md` — решения, факты разведки и вопросы;
- `BENCHMARK_PLAN.md` — испытания.

## 1. Цель MVP

Кроссплатформенное desktop-приложение (Windows и macOS) для локальной транскрибации русских записей длиной 30–60 минут. Что умеет:

- распознаёт аудио, голосовые сообщения (Opus) и аудиодорожки видео MP4/MOV;
- даёт редактировать текст;
- ведёт персональный словарь терминов;
- экспортирует результат в DOCX.

Условия работы:

- без сервера, облачных API и ручной установки инструментов разработчика;
- после однократной загрузки модели — полностью офлайн.

**Стек:**

- оболочка — Tauri 2 + Svelte 5 + TypeScript;
- ядро — Rust;
- движок — отдельный процесс `tolk-engine` с whisper.cpp (large-v3-turbo q5_0 + Silero VAD);
- аудио — Symphonia + libopus + rubato, без FFmpeg;
- хранение — SQLite (rusqlite) + файлы;
- экспорт — DOCX через docx-rs.

Окончательный выбор движка и модели — после бенчмарка. Сильная альтернатива — GigaAM v3 (TD-02, TD-03).

**Поставка MVP:**

- Windows — `.exe` (NSIS, без прав администратора, WebView2 внутри);
- macOS — `.dmg` для Apple Silicon;
- без покупки сертификатов, нотаризации, автообновлений и корпоративного развёртывания (TD-16);
- модели ставятся из приложения (TD-13).

### Ворота (критерии перехода)

- **A1 — движок выбран (после MVP-007):**
  - есть измерения качества, времени и памяти минимум на одной машине Windows и одном Mac;
  - выбор движка и модели по умолчанию записан в TD-02 и TD-03.
- **A — риски движка закрыты (после MVP-011, с учётом MVP-035):**
  - `tolk-engine` обрабатывает 60-минутную запись на целевых Windows и macOS в рамках порогов (BENCHMARK_PLAN §6);
  - проверки устойчивости пройдены: отмена, битые файлы, кириллица в путях, отсутствие GPU и VC++ Redistributable, работа без сети;
  - решение по дополнительному декодеру принято.
  - **До прохождения ворот A полноценный UI не разрабатывается.** Допускается только каркас (MVP-012).
- **B — функционально готово:** все P0-задачи этапов 3–9 закрыты. Сценарий «импорт → очередь → редактирование → словарь → DOCX» работает в dev-сборке на обеих ОС.
- **C — релиз-кандидат:**
  - `.exe` и `.dmg` проверены на чистых системах;
  - сетевой аудит пройден;
  - лицензии проверены;
  - автотесты зелёные;
  - тесты устойчивости пройдены;
  - инструкция готова.
- **D — MVP готов:** выполнены критерии §4 на пилоте.

## 4. Критерии готовности MVP (Definition of Done)

Проверяются на пилоте (MVP-034) на установленных релизных сборках.

**Установка**

- [ ] Сотрудник устанавливает приложение по инструкции, без Java, Python, Node.js, Rust или FFmpeg:
  - Windows 10 22H2 / 11 — `.exe`, без прав администратора;
  - macOS 13+ (Apple Silicon) — `.dmg`.
- [ ] Предупреждения SmartScreen и Gatekeeper проходятся только штатными диалогами ОС. Защита не отключается.

**Модели**

- [ ] При первом запуске приложение определяет ОС, архитектуру и RAM и рекомендует модель.
- [ ] Перед загрузкой показаны название, версия, размер и источник модели.
- [ ] Модель скачивается только после согласия, проверяется по SHA-256, загрузку можно повторить после обрыва; модель не скачивается повторно.
- [ ] При сетевых ограничениях показывается понятная ошибка. Модель можно импортировать из локального файла без сети.

**Импорт и очередь**

- [ ] Импорт одного или нескольких файлов длиной 30–60 мин:
  - MP3, M4A, WAV, FLAC, OGG;
  - Opus — включая голосовые из мессенджеров;
  - аудиодорожка из видео MP4/MOV.
- [ ] Неподдерживаемые и повреждённые файлы отклоняются с понятной причиной.
- [ ] Очередь из 5–6 записей обрабатывается последовательно без вмешательства. Видны состояния QUEUED, PROCESSING, COMPLETED, FAILED, CANCELLED и прогресс. UI не блокируется.
- [ ] Отмена, повтор после ошибки и восстановление после принудительного завершения работают. Одно задание не обрабатывается дважды.

**Результаты**

- [ ] Русский транскрипт отображается и редактируется посегментно. Правки сохраняются и переживают перезапуск и аварийное завершение.
- [ ] Экспорт в DOCX (с таймкодами и без) открывается в Microsoft Word и LibreOffice без ошибок, кириллица отображается корректно.
- [ ] Удаление записи удаляет её аудио и транскрипты. Исходные файлы пользователя не изменяются.

**Словарь терминов**

- [ ] Пользователь добавляет и редактирует термины, экспортирует словарь в файл и импортирует словарь коллеги без дублей.
- [ ] Словарь применяется при распознавании в режиме, выбранном по замерам MVP-037.
- [ ] Эффект словаря измерен и задокументирован. Приложение не обещает исправить все термины.

**Офлайн и производительность**

- [ ] После установки модели все сценарии работают с отключённой сетью. Аудит не выявил незаявленных сетевых обращений.
- [ ] Время обработки, пиковая память, стабильность и качество измерены на доступных устройствах команды и сотрудников (MVP-038). `SYSTEM_REQUIREMENTS.md` содержит только измеренные конфигурации, непроверенные помечены явно, производительность для них не обещается.
- [ ] Измеренные конфигурации укладываются в пороги BENCHMARK_PLAN §6, либо отклонения приняты владельцем.

**Прочее**

- [ ] Нет известных дефектов с потерей данных или падением приложения.
- [ ] Лицензии компонентов и моделей проверены, уведомления включены (MVP-029). Инструкция для сотрудников готова (MVP-033).

## 7. Вне MVP

- Диаризация (разделение по спикерам).
- Запись с микрофона.
- Подпись кода, нотаризация, автообновление — отдельное решение перед релизом.
- Централизованное корпоративное развёртывание.
- Суммаризация и LLM.
- Перевод.
- Синхронизация, облако, центральный сервер словарей.
- Linux, Windows ARM, CUDA, Core ML.
- Параллельная обработка файлов.
- Плеер с подсветкой сегментов.
- Поиск по истории.
- Нечёткое автоисправление терминов.
- Декодирование видеопотока.
- Настраиваемое зеркало моделей.

## 8. После MVP: расширение поддержки устройств (Q-13)

Отдельный этап. Выполняется только после подтверждения спроса и замеров MVP-038. MVP ради гипотетической совместимости не усложняется.

- **Intel Mac** — если такие устройства есть у сотрудников: x64-сборка `tolk-engine` и `.dmg`, только CPU.
- **Слабые ПК:**
  - облегчённые и квантованные модели в каталоге (medium q5_0, small q5_1 или GigaAM — по данным);
  - настройки производительности в UI: потоки CPU, отключение GPU — в протоколе движка они есть с MVP.
- **Предпосылки, заложенные в MVP:**
  - движок без привязки к Apple Silicon (CPU-бэкенд на всех платформах);
  - сборка движка по target triple;
  - модели в каталоге, а не в коде;
  - метрики производительности в приложении (MVP-038).
